# Neowise Candidate Triage

Приложение для предварительной обработки входящих заявок. Модель определяет тему и предлагает черновик ответа; решение об отправке остаётся за менеджером.

## Запуск

Требуется Node.js 20 или новее. Внешних зависимостей и API-ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Для другого порта задайте переменную `PORT`.

## API

`POST /api/triage` принимает JSON с непустым строковым полем `text`.

| Сценарий | HTTP | Ответ |
| --- | --- | --- |
| Корректный результат модели | 200 | `{"status":"ready","topic":"delivery","draft":"..."}` |
| Ошибка ввода или невалидный JSON | 400 | `{"status":"invalid_input"}` |
| Таймаут, ошибка или некорректный результат модели | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

Допустимые темы: `delivery`, `pricing`, `other`. Ответ модели проверяется после JSON-разбора; тема должна входить в список, черновик должен быть непустой строкой. Ожидание модели ограничено 300 мс с отменой запроса по `AbortSignal`.

При ручном разборе интерфейс удаляет предыдущий черновик и предлагает менеджеру обработать заявку самостоятельно. Отправка клиенту не автоматизирована.

## Тесты

```sh
node --test server.test.mjs
```

Тесты используют встроенный `node:test` и временный свободный порт. Проверяются валидные темы, невалидный ввод, все пять сценариев сбоя имитатора и восстановление после ошибки. Для ручной проверки сбоев в тексте заявки можно указать `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]` или `[empty-draft]`.

Результат полезен менеджеру за счёт сокращения времени первичного разбора и исключения ошибочного черновика при сбоях. Эффект можно измерять средним временем обработки и долей заявок, требующих ручного разбора.
